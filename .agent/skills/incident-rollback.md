# incident-rollback

## 适用场景
发布后出现错误率上升、关键链路失败、数据异常。

## 立即动作
1. 停止继续发布/扩散。
2. 记录：版本、提交 SHA、时间、现象、错误日志、影响范围。
3. 判断是否可回滚（本轮无数据库迁移，直接 revert/回滚 tag）。

## 回滚命令
```bash
git revert <bad-sha>
# 或部署侧回滚到上一版本（需真实部署目标）
```

## 验证
```bash
python scripts/e2e_smoke.py
pytest tests/contracts -q
```
健康检查/关键接口/核心链路全部通过才算恢复。

## 记录
- 根因（不是“某个异常”，而是具体代码路径）
- 触发条件
- 为什么现有测试没抓到
- 补的回归测试
- 是否需要轮换密钥（若涉及泄露）

## 常见坑
- 只回滚代码不回滚配置/缓存。
- 回滚后不验证，误以为已恢复。
- 无部署目标却声称已回滚。
