# add-new-feature

## 适用场景
新增用户可见功能（CLI 命令、Agent 能力、工具、工作流阶段）。

## 前置读取
- `workflow_status.md`（当前基线）
- `参考的结果计划指南.md`（能力缺口与已批准范围）
- 相关模块的现有实现（优先复用，禁止重写）

## 步骤
1. 写清成功标准与失败路径（空/超时/权限/重复执行）。
2. 先写失败测试，再写最小实现。
3. 接线检查：功能是否从**生产入口**可达？
   ```bash
   python scripts/reachability.py --prod --list | grep <module>
   ```
4. 增加配置开关时，默认关闭必须在 `doctor` 或启动日志可见。
5. 同步 README、CHANGELOG、MAINTENANCE。
6. 真实 E2E：涉及 LLM/工具/配置时跑 `scripts/e2e_smoke.py`。

## 验收标准
- 单元 + 集成测试覆盖正常/错误/边界。
- 真实入口可触发（不是仅测试可达）。
- 默认关闭的能力有显式提示。
- 文档与行为一致。

## 证据要求
命令、退出码、输出尾部；E2E 必须退出码 0。

## 回滚方式
特性开关可回退；无开关则按提交 revert。

## 常见坑
- 功能已注册但系统提示未注入（本项目 Skill 曾如此）。
- 只改实现不改入口，用户找不到。
- 后台线程初始化失败被 `except: pass` 吞掉。
