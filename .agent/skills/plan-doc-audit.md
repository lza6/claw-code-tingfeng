# plan-doc-audit

## 适用场景
清理“下一步改进指南/优化计划/验收清单”等文档。

## 原则
**未闭环的文档不能删。** 删除前必须逐条审计。

## 步骤
1. 扫描：`计划书/`、`docs/`、根目录含“计划/指南/清单/路线图”的 md。
2. 逐条提取任务：ID、描述、类型、优先级、验收标准、当前状态。
3. 闭环判定必须同时满足：真实实现 + 真实链路 + 真实验证 + 证据。
4. 对“已完成”不采信：跑对应命令验证。
5. 状态分类：已闭环 / 部分闭环 / 伪闭环 / 未闭环 / 需决策 / 已过时 / 不适用。
6. 仍含未闭环 → 保留，并更新顶部状态表为最新实测。
7. 全部闭环 → 归档到 `docs/archive/plans/YYYYMMDD/`，生成 `archive-manifest.md`，列删除清单后再删。
8. 删除后保留回滚方式（归档目录 + git 历史）。

## 本项目现状（2026-10-19）
- `计划书/下一步改进指南.md`：波次 2/3/4/6-8 未闭环（覆盖率、死模块、收集提速），**保留**。
- `计划书/死代码复核报告.md`：维护依据，**保留**。
- `参考的结果计划指南.md`：含部署/Release 阻塞与未达成指标，**保留**。

## 证据
审计报告 `reports/plan-audit-YYYYMMDD.md`；manifest 与删除清单必须可追溯。
