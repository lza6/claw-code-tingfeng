# code-review-checklist

## 适用场景
任何代码改动提交/合并前的独立审查。

## 审查心态
有罪推定；评估成品不评估意图；忽略“以后修”。

## 阻断级（必须修）
- 安全漏洞：路径遍历、SSRF、注入、密钥硬编码、越权。
- 数据损坏/丢失：非原子写、读改写无锁、迁移不可逆。
- 逻辑错误：状态机错误、错误被吞、失败被当成功。
- 竞态：共享状态无同步、TOCTOU。
- 伪造验证：声称通过但无命令输出。

## 高风险信号
- 变量遮蔽模块导入（如把 `error` 当循环变量）。
- 异常分支里 `continue` 后留下悬空状态（原生 tool_call_id）。
- 锁只包住写、没包住读改写。
- 测试复制生产逻辑再断言（虚假覆盖）。
- 只跑 `src/` 的 lint 而 CI 跑 `src/ tests/`。

## 审查输出
Summary / Critical Issues / Required Changes / Suggestions / Verdict。

## 验收
- 阻断项清零；修复后有对应回归测试。
- 复验只针对修复点与相邻回归。
- 最多 3 轮；未 Approve 必须记录阻塞。
