2. 关键决策

默认关原生工具调用（CLAWD_NATIVE_TOOLS=1 开启），流式显式回退
pyproject版本真相源优先，避免 editable 元数据滞后
请求前SSRF 重定向逐跳校验，而非事后检查
按序对应tool_call_id 与调用顺序一一对应，不用签名映射

6. 测验（必须通过）

共 9 题，全部答对判定“通过”。提交后会显示解释与正确/错误标记。

1. 原生 function calling 的默认状态是？

默认关闭以保持既有文本协议行为；开启后非流式路径使用原生调用，流式会显式告警并回退。

2. CI 的阻塞式 lint 检查覆盖哪些路径与规则？

只拦截必然导致运行时崩溃的硬错误；全量 1697 条历史违规作为非阻塞报告，独立批次清理。

3. 文件锁的正确语义是？

只锁写仍会丢更新；owner token 防止误删他人锁；原子回收陈旧锁避免与新持有者竞争。

4. Scrape 的 SSRF 重定向校验发生在什么时候？

事后校验时内网请求已经发出；httpx 手动逐跳、urllib 自定义 handler、Playwright route 均在请求前拦截。

5. Skill 如何注入系统提示？

渐进披露：常驻上下文只放摘要，避免提示膨胀；SkillTool 只能读取发现清单中的技能，防止路径遍历。

6. 版本号的真相源优先级是？

editable 安装的 metadata 会滞后；源码树中 pyproject 始终是最新值，避免不同解释器显示不同版本。

7. 为什么本轮没有删除计划文档？

覆盖率、死模块、收集提速仍未闭环；死代码复核报告仍是维护依据。删除前必须全部闭环并归档 manifest。

8. 当前部署与 GitHub Release 状态是？

不得假装已上线；最小下一步是提供 gh 登录与 Docker/部署目标。

9. Windows 上状态快照曾保存失败，根因是？

该平行实现已改为跨平台锁；真正的生产路径 core/persistence/run_state.py 也在 v0.60.6 修复（固定 tmp/无锁/无 fsync）。
