## 第 0 章 给执行者的使用说明

### 0.1 这份文档要解决什么

本指南**不是**一份"许愿清单"，而是一份**基于实测证据的缺陷与演进台账**。每一条改进项都满足三个条件：

1. **有证据**：来自真实运行的命令输出、静态分析结果或具体到 `file:line` 的代码阅读。
2. **有验收标准**：写清楚"怎么算做完了"，以及用哪条命令验证。
3. **有依赖顺序**：标明前置任务，避免"前面改 bug、后面加功能、又出新 bug"的死循环。

### 0.2 执行者的强制工作流

> 执行任何任务前，先读本指南对应的章节，再动手。**禁止跳章执行**。

```text
Inspect   → 读本指南第 1/2 章，理解现状与根因
Assess    → 用附录 A 的命令复现证据，确认问题仍然存在
Plan      → 按第 13 章的波次表，取当前波次未完成任务
Act       → 单任务单提交，禁止一个提交混多个不相关改动
Validate  → 运行该任务验收标准里的命令，粘贴真实输出
Review    → 独立审查（不由实现者自审）
Converge  → 达标即停，不追求"完美"
Report    → 报告附证据，未运行的验证必须显式声明"未运行"
```

### 0.3 三条铁律

| 编号 | 铁律 | 反面案例 |
|:---|:---|:---|
| **R1** | **不重写文件，只做外科手术** | 把 `src/workflow/engine.py`(1408 行) 推倒重写 → 引入新 bug，违背用户约束 |
| **R2** | **优先复用已有轮子** | 新写一个通知模块，而项目已有 3 个（见 §1.3.1） |
| **R3** | **未运行 ≠ 通过** | 声称"测试通过"却拿不出命令输出 → 视为未完成 |

#### 1.3.2 问题二：契约漂移——测试与实现各说各话

**已验证的失败清单**（`python -m pytest tests/utils tests/contracts`）：


| 测试文件 | 失败原因 | 根因（已读码确认） |
|:---|:---|:---|
| `tests/contracts/test_agent_registry_stability.py` (5 例) | `TypeError: AgentDefinition.__init__() got an unexpected keyword argument 'reasoning_effort'` | 实现改成了 camelCase `reasoningEffort`（`src/agent/definitions.py:62`），契约测试仍用 snake_case |

| `tests/workflow/test_verifier.py`（**收集失败**） | `ImportError: cannot import name 'TaskSize' from 'src.workflow.verifier'` | `TaskSize` 枚举被替换为 `determine_task_size()` 函数（`verifier.py:123`） |
| `tests/self_healing/test_engine.py`（**仅在全量收集中失败**） | 单独运行可正常收集 | **pytest `import file mismatch`** —— 见下方修订 |
| `tests/tools_runtime/test_types.py`（**仅在全量收集中失败**） | 单独运行可正常收集 | 同上 |

> **⚠️ 本行原始推断已被证伪（2026-10-16 修订）**
>
> 首版把这两处收集失败归因为"测试间状态污染 / 收集顺序依赖"，**这是错的**。
> 真实原因是 **pytest 的 `import file mismatch`**：`tests/` 下存在同名文件
> （`test_engine.py` ×2、`test_types.py` ×2），而多数子目录缺少 `__init__.py`，
> pytest 便以裸文件名作为模块名，第二个撞上第一个。报错信息其实已经写明：
>
> ```text
> import file mismatch:
> imported module 'test_engine' has this __file__ attribute:
>   ...\tests\runtime\test_engine.py
> which is not the same as the test file we want to collect:
>   ...\tests\self_healing\test_engine.py
> ```
>
> 修复：补齐 14 个缺失的 `tests/*/__init__.py`，使模块名全限定化。
> 结果：收集错误 **4 → 0**，用例 2769 → 2857，耗时 306s → 126s。
>
> **教训**：把"复现不了的失败"直接归因为"状态污染"是一种懒惰的推断。
> 报错信息里已经有确定性答案时，应当读它，而不是重新猜测。

> **`AgentDefinition` 的 camelCase 问题**：`src/agent/definitions.py` 整个字段集为 `reasoningEffort / posture / modelClass / routingRole / tools / category`，是 TypeScript 命名直接搬进 Python dataclass 的产物（文件头注明"借鉴 oh-my-codex"）。这违反 PEP 8，且已导致契约测试失败。**修复建议见 §4.2**。

#### 1.3.3 问题三：静默失败掩盖真实缺陷

**已验证**：`src/brain/world_model.py:224-232`（World Model 初始化后的 RAG 指标发布）

```python
    metrics = {
```

## 第 2 章 根因分析（第一性原理）

### 2.1 为什么会有 213 个死模块？

**第一性原理**：一个模块要"活"，必须在运行时被**可达路径**引用。可达路径只有三种：静态 `import`、注册表登记、动态加载。

用这个判据回看项目历史（`git log --oneline`）：

```text
7ebd096 Merge remote changes and resolve conflicts
f5f369d Initial commit
e855964 Initial commit: Clawd Code AI coding agent framework
1dd3c33 feat: integrate oh-my-codex keyword detection and intent routing
8b203cc chore: init gsd
a12cf68 Initial commit: GoalX integration baseline
```

这是一条**"集成波次"轨迹**，而非**"演进轨迹"**：

| 波次 | 引入方 | 新增目录 | 是否接入主链路 |
|:---|:---|:---|:---|
| 第 1 波 | 本体（Aider 风格） | `src/notification/`、`src/session/`、`src/cli/aider_commands_*.py` | ✅ 部分 |
| 第 2 波 | GoalX | `src/core/durable/`、`src/core/budget_guard.py`、`src/workflow/worktree_isolation.py` | ✅ 部分 |
| 第 3 波 | oh-my-codex | `src/notifications/`、`src/visual/`、`src/session_history/`、`src/pipeline/`、`src/hooks/extensibility/` | ❌ **移植但未接线** |
| 第 4 波 | ClawGod / Onyx | `src/core/exceptions.py` 追加段、`src/core/tracing/`、`src/core/observability/` | ⚠️ 覆盖式追加 |

**根因结论**：每一波都遵循"**移植源项目目录结构 → 落盘 → 声称完成**"，但**缺少"接线验证"这一环节**。当 `import` 从未被写进任何可达路径时，移植的代码就是**化石**。

### 2.2 为什么静态检查有 58 个"未定义名称"却没人发现？

**第一性原理**：`F821` 是**运行期 `NameError` 的静态代理**。它能存活的原因必然是——**那段代码从未在测试中被执行**。

交叉验证：`src/brain/world_model.py`（含 F821）在 `coverage.json` 中的状态。全项目覆盖率 19.51%，`src/brain/` 下 3 个模块被判定为死模块。**未覆盖 → 未执行 → 未发现**。

**根因结论**：低覆盖率不是"质量指标问题"，它是**缺陷检测能力的缺失**。19.51% 覆盖率意味着 **80.49% 的代码从未被任何测试触碰过**。

### 2.3 为什么会有 255 处静默吞异常？

**第一性原理**：`except Exception: pass` 是**"让测试变绿"的最短路径**。

典型场景：某人给 `world_model.py` 加了一段指标发布代码，发现初始化时会抛 `NameError`，测试挂了。最短修复路径不是"找到 `indexed_count` 该赋什么值"，而是"包个 try/except 吞掉"。**测试绿了，功能死了。**

**根因结论**：这是**验证标准被短路**的产物。当"测试通过"成为唯一验收信号时，`except: pass` 就是对验证标准的**作弊**。

### 2.4 三者的共同上游：缺少"可达性契约"

```text
缺少可达性契约
   │
   ├─→ 移植代码不接线        → 213 个死模块（§1.3.1）
   ├─→ 不接线就不进测试      → 覆盖率 19.51% → F821 存活（§2.2）
   ├─→ 测试失败用 except 掩盖 → 255 处静默吞掉（§2.3）
   └─→ 文档写"已完成"        → README 虚报覆盖率（§1.3.4）
```

**本指南此后所有改进项，都以"重建可达性契约"为纲。**

### 4.1 【P0-1】Windows 中文环境启动时 UnicodeEncodeError

**证据状态**：`已验证`

**复现命令**：
```bash
PY="C:/Users/Administrator.DESKTOP-EGNE9ND/AppData/Local/Programs/Python/Python310/python.exe"
"$PY" -m src.main doctor
```

**实测输出（节选）**：
```text
--- Logging error ---
UnicodeEncodeError: 'gbk' codec can't encode character '\u26a0' in position 41: illegal multibyte sequence
Call stack:
  File "...\src\main.py", line 222, in main
    initialize()
  File "...\src\main.py", line 85, in initialize
    log_pricing_check()
  File "...\src\core\cost_estimator\cost_estimator.py", line 386, in log_pricing_check
    warn(freshness['warning'])
  File "...\src\utils\logger.py", line 57, in warn
    self.logger.warning(msg, extra={"props": props})

```

**根因（已读码确认）**：`src/utils/logger.py:92`

```python
console = logging.StreamHandler(sys.stdout)   # ← 未指定 encoding
```

Python 3.10 在中文 Windows 上 `sys.stdout.encoding == 'gbk'`，而日志含 emoji `⚠️`（U+26A0 U+FE0F）与中文。`StreamHandler` 无 encoding 时使用 `sys.stdout.encoding` → 编码失败。

同时，整个程序的中文控制台输出**全部显示为乱码**（实测输出中 `工作目录` 显示为 `����Ŀ¼`）。

**修复方案（两处，最小改动）**：

1. **`src/utils/logger.py`**：给 `StreamHandler` 显式指定编码与错误策略
   ```python
   console = logging.StreamHandler(sys.stdout)
   if hasattr(console.stream, 'reconfigure'):
       console.stream.reconfigure(encoding='utf-8', errors='replace')
   else:
       console = logging.StreamHandler(sys.stdout)
       console.setFormatter(...)
   ```
   > 说明：Python 3.7+ 的 `TextIOWrapper.reconfigure()` 是标准做法。**不要**用 `logging.StreamHandler(stream)` 的 `encoding` 参数直接构造，因为 `StreamHandler` 在 Python 3.8 及以前不接受也已接受的 stream 带 encoding（取决于版本），`reconfigure` 是最稳妥的写法。

2. **`src/main.py`** 的 `initialize()` 开头，在**任何输出之前**统一设置：
   ```python
   for _stream in (sys.stdout, sys.stderr):
       if hasattr(_stream, 'reconfigure'):
           _stream.reconfigure(encoding='utf-8', errors='replace')
   ```
   并在 `start.bat` 已有的 `chcp 65001` 基础上，补充设置 `PYTHONUTF8=1` 环境变量（Python 3.7+ 的 UTF-8 模式）。

3. **降级 emoji**：日志中的 `⚠️` 建议替换为 ASCII 标记（如 `[WARN]`），因为**日志会被写入无 TTY 的场景**（CI、Docker、重定向），此时 `errors='replace'` 会把 emoji 变成 `?`，仍不理想。

**验收标准**：
```bash
# 1. 无 UnicodeEncodeError
"$PY" -m src.main doctor 2>&1 | grep -c "UnicodeEncodeError"   # 期望输出 0
# 2. 中文正常显示（非乱码）
"$PY" -m src.main doctor 2>&1 | grep -c "工作目录"              # 期望输出 ≥ 1
# 3. 管道重定向不崩
"$PY" -m src.main doctor > /tmp/out.txt 2>&1; echo $?          # 期望 0
```

**风险**：低。`reconfigure` 对已重定向的流安全。

#### 6.3.3 TDD 执行模板（每个任务必须遵循）

```text
1. RED     → 写测试，运行，确认失败。粘贴失败输出。
2. GREEN   → 用最小改动让测试通过。粘贴通过输出。
3. REFACTOR→ 在不改行为的前提下改善结构（可选，仅当有明显坏味道）。
4. COVER   → 运行覆盖率，确认该文件覆盖率提升。
5. COMMIT  → 单文件/单模块一个提交。
```

**AAA 结构强制**：
```python
def test_returns_empty_when_no_task_size_matches():
    # Arrange
    query = ""
    # Act
    result = determine_task_size(query)
    # Assert
    assert result == TaskSize.SMALL
```

**测试命名强制**：`test_<被测行为>_<条件>_<预期>`

**禁止**：
- ❌ 为通过测试而削弱断言
- ❌ `pytest.skip` 掩盖未实现功能
- ❌ `assert True`

### 11.5 错误码体系

```python
class ClawdError(Exception):
    code: str = "CLAWD-E0000"      # 稳定可搜索
    user_message: str               # 给用户看的一句话
    action: str | None = None       # 建议动作

# 示例
class PatchApplyFailed(ClawdError):
    code = "CLAWD-E3101"

```

**价值**：错误码是**可观测性 + 用户支持**的基础设施。配合 `CHANGELOG` 与文档，用户可自助排障。

```python
import ast
from pathlib import Path

modules = {}
for p in Path('src').rglob('*.py'):
    parts = list(p.with_suffix('').parts)
    if parts[-1] == '__init__': parts = parts[:-1]
    if parts: modules['.'.join(parts)] = p

imported = set()
for f in list(Path('src').rglob('*.py')) + list(Path('tests').rglob('*.py')):
    try: tree = ast.parse(f.read_text(encoding='utf-8', errors='ignore'))
    except Exception: continue
    fp = list(f.with_suffix('').parts)
    if fp[-1] == '__init__': fp = fp[:-1]
    for node in ast.walk(tree):
        if isinstance(node, ast.Import):
            for a in node.names: imported.add(a.name)
        elif isinstance(node, ast.ImportFrom):
            mod = node.module or ''
            if node.level:
                base = fp[:len(fp)-node.level]
                mod = '.'.join(base + ([mod] if mod else []))
            if mod: imported.add(mod)

refd = {m for m in modules for imp in imported if imp == m or imp.startswith(m + '.')}
dead = [(m, str(p), len(p.read_text(encoding='utf-8', errors='ignore').splitlines()))
        for m, p in sorted(modules.items()) if m not in refd and m.count('.') > 0]
print(f'TOTAL={len(modules)} DEAD={len(dead)} LINES={sum(d[2] for d in dead)}')
```

### B.1 术语

| 术语 | 含义 |
|:---|:---|
| **可达性契约** | 一个模块必须能被运行时到达（静态 import / 注册表 / 动态加载）才视为"活的"。本指南 §2.4 的核心概念 |
| **契约测试** | 锁定公共 API 签名与行为的测试。本项目 `tests/contracts/` 属此类 |
| **契约漂移** | 实现改了 API，但调用方/测试未同步，导致失败。§1.3.2 |
| **静默失败** | 异常被 `except: pass` 吞掉，功能失效但无任何信号。§1.3.3 |
| **叠加式集成** | 新需求通过"复制源项目目录"实现，而非融入现有架构。§2.1 |
| **外科手术式修改** | 只改动必须改的行，不重写文件。§0.3 R1 |
| **绝对指标** | 覆盖率行数、用例数等绝对值，用于防止"删代码刷百分比"。§15.2 |
